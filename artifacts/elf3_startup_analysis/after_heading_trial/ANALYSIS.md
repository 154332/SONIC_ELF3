# heading 对照之后的起步分析

用户实测：完整朝向 YAML 效果更差；原 heading 配置下无拉力不按 T 可站稳至少 5 秒。
因此暂不以独立静止站立失败为主因，也不能以单项朝向替换作为已验证修复。配置差异仍存在，但其因果优先级降低。

## 当前最强证据

1. 训练 config 的 joint_velocity_range=[0,0]。初始化直接取 motion joint_vel，没有额外关节速度扰动，更不是将动态 walk 所有关节速度置零。walk PKL 首帧有限差分速度 RMS=1.735358 rad/s。机器人能静止站稳，不等于能从零速度启动这个 walk。
2. 当前部署暂停时未来窗口全是同一帧 q 和零 dq；播放时才出现逐帧变化的未来参考。训练窗口由时间连续运动产生，现有 freeze-frame 增强是运动尾部冻结，不提供冻结之后再恢复播放的连续起步阶段。
3. 当前 blend 位置 q=(1-a)q0+a*qw，速度 dq=a*dqw。若游标以正常速度推进，其位置导数另有 a_dot*(qw-q0) 项。1 秒线性 blend 的第 0.2/0.5/0.8 秒，省略项各关节 RMS≈0.1435/0.2039/0.3364 rad/s；第 0.8 秒最大≈1.1444 rad/s。此项是参考一致性问题，不是对电机直接下发的速度，也不能证明补项必然提升策略效果。
4. blend 期间游标不等支撑切换，0.5 秒已到 frame25；机器人可能尚未迈开而参考已推进。更长 blend 可以减小突变，却可能进一步压小起步动作。
5. 训练 TensorBoard 第10000步 foot_pos_xyz 终止统计≈0.43156，time_out≈0.53784，anchor_ori_full≈0.03288。foot_pos_xyz 对应左右 ankle body 相对对齐目标的三维位置误差阈值0.2m。这是训练日志指标，含采样和随机化等条件，不能当作部署跌倒率或无噪声评估成功率。末尾100个记录均值见 training_metrics.json。

## 建议的区分试验

保留原 heading YAML。固定 checkpoint/reference/初始条件，先比较 blend=0、0.2、0.5、1.0，记录首次迈步时间及起步后3秒持续行走结果。
在 IsaacLab 无随机化、确定性策略评估中，先做按参考姿态/速度初始化的 walk；再做同姿态、接近零速度初始化。若前者可靠而后者失败，优先连续起步训练；若前者也失败，优先改善动作跟踪训练/数据；若 IsaacLab 两者可靠但部署失败，优先排查转换、时序与物理参数。
仅移除拉力前后改变模型或增益无法区分这些原因。

本次没有修改现有代码、配置或 ONNX，没有执行闭环试验。
